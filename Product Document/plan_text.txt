JIBBLE 30-DAY DEVELOPMENT PLAN
=================================
Goal: Build the first functional version of the Jibble app (backend + Flutter mobile + basic infra + admin panel v1) in 30 days, following th
Assumptions
-----------
- Solo developer (you), 5–8 focused hours per day.
- Tech stack: Node.js + Express + PostgreSQL (Neon), Redis, S3/Cloudinary, Socket.io, Flutter (Riverpod or similar), basic CI/CD.
- You already have VS Code, Flutter SDK, Node, Git, and GitHub set up.
- Scope: MVP-quality implementation of the core features from the PRD + minimal admin panel (just enough for seeding/management).
Legend
------
- BE = Backend
- FE = Flutter mobile app
- ADM = Admin panel (web)
- INF = Infrastructure / DevOps
- DOC = Documentation
Week 1 – Project Setup, Auth, and Core Foundations (Days 1–7)
------------------------------------------------------------
Day 1 – Monorepo & Repo Setup
- Create monorepo root `jibble/` with `apps/`, `backend/`, `infrastructure/`, `database/`, `shared/`, `docs/`.
- Initialize Git repository and create main branches (`main`, `dev`).
- Add base `README.md` describing project, tech stack, and folder structure.
- Setup backend Node project (package.json, tsconfig, basic `src/index.ts`, `src/app.ts`).
- Setup Flutter project under `apps/mobile_app/` (run `flutter create`).
Day 2 – Backend Core Config & Env
- Implement `backend/src/config/env.ts` with dotenv + schema validation.
- Implement `db.ts`, `redis.ts`, `s3.ts`, `cloudfront.ts`, `logger.ts`, `requestContext.ts`.
- Implement middlewares: `correlation.middleware.ts`, `requestLogger.middleware.ts`, `error.middleware.ts`.
- Add `api/v1` router entry and mount a health-check route (`GET /api/v1/health`).
- Create `.env.example` with all required keys.
Day 3 – Database Schema & Migrations
- Design/confirm core tables in `database/schema.sql` (users, profiles, colleges, posts, stories, comments, likes, follows, messages, events, g
- Implement SQL migrations in `backend/src/db/migrations/*`.
- Implement migration scripts (`infrastructure/scripts/migrate_db.sh`, `rollback_db.sh`).
- Run migrations against local/Neon DB and verify tables.
Day 4 – Auth Module (BE) – Entities & Repositories
- Create `modules/auth/` and `modules/user/` folders.
- Define `user` entity in ORM/schema and `user.types.ts`.
- Implement `user.repository.ts` (create user, find by id/email/username, update basic fields).
- Implement `auth.repository.ts` for tokens/sessions if needed.
- Add `auth.validation.ts` (signup, login, refresh, reset password).
Day 5 – Auth Module (BE) – Services & Controllers
- Implement `auth.service.ts` (signup, login with password, token generation, refresh, logout).
- Implement `auth.controller.ts` + `auth.routes.ts` under `/api/v1/auth`.
- Wire in rate limiting for auth (`rateLimiter.auth.ts`).
- Add unit tests for core auth flows in `tests/auth.test.ts`.
Day 6 – Flutter Setup & Auth Screens (FE)
- Setup base Flutter architecture: `core/`, `features/`, `shared/` as per blueprint.
- Implement `core/network/api_client.dart`, `endpoints.dart`, `network_interceptor.dart`.
- Build UI for `splash_screen.dart`, `login_page.dart`, `register_page.dart`, `otp_verification_page.dart` (if used).
- Setup state management for auth (`auth_provider.dart`).

Week 2 – Onboarding, Profiles, Feed, and Posts (Days 8–14)
----------------------------------------------------------

- Implement `college` module (controller, service, repository, routes) for listing/selecting colleges.
- Implement `profile` module with profile fields from PRD (name, username, dob, interests, skills, etc.).
- Add endpoints for updating profile and fetching own profile.
- Seed `colleges` table with ~20 initial entries using `seed_colleges.ts`.
Day 9 – Onboarding Flow (FE)
- Implement onboarding screens: `college_page.dart`, `date_of_birth_page.dart`, `interests_page.dart`, `skills_page.dart`, `profile_picture_p
- Connect these screens to BE endpoints (colleges list, profile update, file upload for profile picture).

Day 10 – Feed & Post Entities (BE)
- Implement `post` module entities and DB relations (posts, likes, comments, categories).
- Implement `post.repository.ts` with queries for:

- get home feed (paginated)

Day 12 – Home Feed UI (FE)

- Implement `feed_post_card.dart`, `stories_row.dart`, `category_chips_row.dart`.

Day 13 – Create Post UI (FE)

Day 28 – Hardening: Validation, Errors, and Security
- Review all endpoints for input validation (zod/joi schemas).
- Make sure all errors go through `error.middleware.ts` with consistent structure.
- Verify auth + RBAC on protected routes (Circle, Chat, Admin, etc.).
- Double-check CORS, HTTPS assumptions, and secure headers via Nginx or Express.
Day 29 – End-to-End Testing & Bug Fixes
- Run manual flows on a real device/emulator:
- Sign up → Onboarding → Home → Feed → Circle tabs → Chat → Notifications.
- Try from at least 2 different test users.
- Fix high-priority bugs found during flows.
- Do quick performance check (basic profiling of slow endpoints).
Day 30 – Cleanup, Documentation, and Launch Prep
- Update `docs/architecture.md` and `docs/api-design.md` to reflect the final implementation.
- Write a short deployment playbook (how to deploy backend, run migrations, seed data).
- Ensure `.env.example` is fully updated.
- Clean up TODO comments and dead code.
- Tag a `v0.1.0` release in Git and write release notes.
